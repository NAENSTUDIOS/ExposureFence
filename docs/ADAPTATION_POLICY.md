# ExposureFence — Verified Adaptation Policy (ASIVE Policy Guard)

**Policy Identifier:** `ASIVE_VERIFIED_ADAPTATION_V1`  
**Quality Score Threshold:** $\ge 90.00\%$  
**Decision Authority:** `policy:ASIVE_V1`  
**Execution Plane:** Sandboxed Simulation & Review Route  

---

## 1. Overview & Adaptation Lifecycle

The Adaptive Security Intelligence & Verified Evolution Engine (ASIVE) evaluates candidate platform improvements (such as new YAML rules, connector patches, test expansions, and local cache maintenance) through a strict 13-state lifecycle:

```
[DETECTED] ──▶ [CLASSIFIED] ──▶ [INVESTIGATING] ──▶ [SOLUTION_PROPOSED]
                                                            │
                                                            ▼
[APPROVED_FOR_REVIEW] ◀── [SANDBOX_TESTING] ◀── [EVALUATION_PENDING]
         │                          │
         ▼ (Human Admin Approval)   ▼ (90%+ & Non-Sensitive)
[APPROVED_FOR_INTEGRATION]  [APPROVED_FOR_INTEGRATION]
         │                          │
         └────────────┬─────────────┘
                      ▼
                 [RESOLVED] (or [ROLLED_BACK] on regression)
```

---

## 2. 10-Dimension Solution Ranking Rubric

Candidate solutions generated by the Autonomous Solution Engine are scored across 10 evaluation dimensions (100 points maximum):

1. **Security Effectiveness (15 pts):** Degree to which the solution closes the underlying attack vector or threat pattern.
2. **Evidence Quality (12 pts):** Confidence and corroboration of the triggering observation.
3. **Compatibility (12 pts):** Preserves existing APIs, contracts, and database schemas.
4. **Regression Risk (12 pts):** Inverse score based on risk of breaking existing tests.
5. **Reversibility (10 pts):** Completeness and determinism of the rollback plan.
6. **Operational Cost (10 pts):** Zero out-of-pocket cost score (offline = 10.0).
7. **Complexity (10 pts):** Maintainability and code simplicity.
8. **Maintainability (10 pts):** Documentation, modularity, and clean separation of concerns.
9. **Confidence (10 pts):** Confidence score of the problem classification.
10. **Problem Coverage (9 pts):** Breadth of symptoms and root causes addressed.

---

## 3. Mandatory Security Gates & Human Review Route

Regardless of the ranking score:
- **Sensitive Security Code:** Any solution modifying YAML detection rules (`R01`–`R07`), IAM heuristics (`ESC-01`–`ESC-06`), or governance policies **cannot** be auto-integrated. It transitions to `APPROVED_FOR_REVIEW` requiring independent human review.
- **AI Agent Authority Ban:** The AI agent is strictly barred from calling `initiate_adaptation()` or `rollback_adaptation()`.
- **Zero Cloud Mutation:** Candidates proposing destructive cloud operations (`delete_*`, `terminate_*`) fail sandbox evaluation immediately.
